## 一、病根（先核世界模型，再动手）

判把握度的规则写在三份 SKILL 里，判词只有一句「多数说法只有单一来源时写低」。
真机 r-3b3482ca7f8b：主张 1358 条、单源 1254 条（92.3%）。**这个比例不是结论

它结构上只会挂一条证据。所以这条规则在本形态语料上几乎恒为「低」，

## 三、五货的做法与关键取舍

### 货 1 把握度按条分层（`run.finding_confidence`）

三档的界写死：**高** = ≥2 个独立出处 + ≥2 个平台 + 最强等级 A/B + 有多源印证 +
编码格 ≥10 条（五条全中）；**中** = ≥2 个独立出处 + 最强等级 A/B + （跨平台或有量）；
其余 **低**。整篇取各条中位档、偶数条取更弱的那一档（`run.overall_confidence`）。

真机四条判出 **低 / 中 / 高 / 低**，与用户自己读出来的强弱次序一致。
⛔ 没有把「低」直接改成「中」：整篇总括仍是「低」，但读者现在看得见第 3 条是高。

两处**实测踩过的坑**，都已写进代码注释：

1. `Finding.marks` 是裸的 `S01`、正文里是 `[S01]`。第一版只用了认方括号的 `_MARK`，
   四条齐刷刷判「没带角标 ⇒ 低」，看着像「规则没生效」，其实是尺子自己读不到。
2. 「有多少条评论撑着」只能读 `attitude_by_topic`（主题 × 态度）。并入
   `scenario_counts`（一格 44 条，只答「在哪谈」）或 `scenario_attitude` 的「其他」
   兜底桶，会把第 4 条（同帖两条评论）和第 2 条（付费）双双抬成「高」。

### 货 2 内部计数挪进附录

摘要那一行不再印「主张 1358 条：单源 1254 / …」。真实数字一个没改，整段落到附录
「把握度读数」，配一句人话说清它为什么天生偏大。摘要换成逐条报档 + 总括怎么汇总。

### 货 3 标题不得大过证据（`run.oversized_finding_lines` / `oversized_shard_title`）

只管把握度判「低」的那几条，两条判词：① 标题不许出现普遍化断言词；
② 发现行必须交代证据规模或范围。二级标题只管 ①（标题是一句结论，塞进口径会写成口径行）。

**挡在写作期**（`_write_target`）而不是只留给验收：红一条 = 重写一片；
留给尺子要等整轮跑完（§WRITE-1 货 4 同一条道理）。尺子那头留同名判据作兜底，
两处 import 同一个函数。

### 货 4① 负向可追溯（`run.attitude_traceability`）

摘要态度行由程序带出：「其中负向 17 条里有 2 条点得到原文（[S17][S21]），
其余 15 条本轮没进引用池、正文点不到原文」。条数与角标同一张表同一次读，
⛔ 不另算一遍。写手不必再写、也没法写错。

### 货 4② 单人线索节（`tables._clues` + `run.clues_block`）

**⚠️ 本包最关键的一处翻案**：提货单点名的那五条信号（Windows 输入法起步晚、
每天打视频电话「要疯了」、造 AI 黄谣、《海阔天空》非粤语、「用了俩礼拜一分钱没花」），
`citation_no` **全是 `None`**——它们是 C 级评论，本轮压根没进引用池。
所以线索**不要求进池**，没进池的写明「本轮未进引用池，点不到原文」
（与货 4① 同一条道理：说清楚比藏起来强）。没角标的行不违反尺子③——
③ 查的是「出现的角标在不在池里」，不是「每行都得有角标」。

另外三处取舍：

- **归程序块、归附录**：§SEL-1 已查实写手正文 8674 字符、带宽上限 9000，
  再要它多写一节只能靠删限定句。程序块不计入写手篇幅，所以这一节是**加出来的**。
  实测：修后稿 ⒝ 篇幅仍判 OK。
- **摆成表不是列表**：尺子④ 按行扫数字、表格行整行跳过；线索原文常带数字，
  而那些数字的出处就是那条评论本身、不在任何聚合表里。
- **封顶封在剔除之后**：第一版先封 8 条再剔除正文引过的，筛完只剩 2 条，
  而且用户点名要的那几条全被挡在名额之外。

次序按主张在库里的登记次序，⛔ 不按重要性（那是模型判断，本块不经模型），
也不按字数——实测最长的那句往往是最啰嗦的那句，真正具体的反而被挤掉。

### 货 5 建议与证据匹配（`run.weakevidence_advice`）

与 `singlesource_advice` 是**扩展不是另起一套**。分工写死：前者管交叉验证结论
（全是孤证 ⇒ 降级），后者管证据强度（把建议所引角标当成一条发现判把握度，
判「低」⇒ 降级**或**在依据行写明 `把握度：低（理由）`）。
两道切的是同一批**编号条目**（新抽出的 `advice_entries`，一处定义两处用），
降级区之后都不管，所以不会一道说降级另一道说不用管。

## 四、读数不全就一条都不判（`run.tiering_available`）

分层把握度的三条腿里，「编码格有多少条」是本包新加的那一条，也正是旧规则
「完全不看」的那一条。它不在场时判出来的还是老口径，摆出来只会让每条齐刷刷显示
「低」——那是本包要治的病。所以**没有已编码 UGC 的稿（纯媒体材料的竞品矩阵等），
显示与门禁一起退场，行为一字不变**。⛔ 不做「缺了就按两条腿判」的兜底。

## 七、留给调度的话

1. **重出那一轮会看见什么**：摘要开头不再是「把握度低 + 单源 1254」，
   而是逐条报档（真机是 低/中/高/低）+ 总括怎么汇总；附录多两块

3. **没动的**：海外源「旁证不进关键发现」那道闸（§RPT-4 有意加的）本包照办、
   ⛔ 没绕过——线索区也按它筛。要不要撤是用户的拍板题。
4. **与 §RPT-7 的接缝**：本包动了 `run.py` 的 `assemble` / `PROGRAM_APPENDIX_HEADINGS`
   与 `tables.build_tables` 的返回字典，**没碰** `missing_table` / `_chapter_label` /
   `_MISSING_REASON`。合入时若 RPT-7 也加了程序块常量，两边都要出现在
   `PROGRAM_APPENDIX_HEADINGS` 里（那是「剜哪些块」的唯一答案）。
