## 二、货 1：闸认两种形态（`app/report/polish/run.py`）

新增 `_DOWNGRADE_ENTRY_HEAD`，在按条切分之前先判一次；命中就 break，
已攒的 `current`（前缀之前的那些条）留给循环外收尾、照旧判。

```python
_DOWNGRADE_ENTRY_HEAD = re.compile(
    r"^\s*\d+[.)、]\s+[*_~`“\"'「『（(【\[]*\s*" + re.escape(DOWNGRADE_HEADING))
```

**判定范围写窄（防放宽过头）**：只到「条目号 + 紧跟的强调/引号标记之后**紧接**该词」。
⛔ 没有放宽成「整行任意位置出现该词即 break」——那样写手在一条普通建议里顺口提一句
「这条也算值得进一步验证的方向」，后面整段建议就全免检了，等于把闸修哑。
条目号的形态跟 `_ENTRY_HEAD` 对齐（`\d+[.)、]` + 至少一个空白），⛔ 没顺手把无序列表 `-`
也认进来：那不是提货单说的「条目号」，且容易被前言里的一句罗列误触发。

`#` 开头那一支一个字没动，独立小标题的老行为原样保留。
